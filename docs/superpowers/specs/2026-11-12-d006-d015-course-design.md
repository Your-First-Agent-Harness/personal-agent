# D006–D015 课程重排设计

日期：2026-11-12  
状态：课程编排已确认，待书面规格复核

## 1. 背景与目标

D005 已提前完成原任务卡中的部分后续内容：消息角色、`ToolCall`、工具 Schema、工具注册、OpenAI-compatible `tool_calls`、`read_file`、多轮工具调用 Loop 和错误回喂。继续照搬 D006–D012 会重复实现。

本设计保留 D006–D015 的分支编号和计划日期，但将课程重排为十条不重复、可独立验证的教学快照。完成后，Personal Agent 应具备事件观测、多轮会话、上下文裁剪、取消、写入与编辑文件、执行命令、标准化错误和综合修复能力。

## 2. 当前基线与收尾

D005 已提交并合并 `main`，31 个测试通过。开始 D006 前完成以下收尾：

- 在 `.gitignore` 中保留 `.env`、`.env.*` 的忽略规则，并通过 `!.env.example` 允许提交模板。
- 提交不含真实密钥的 `.env.example`，只包含模型、地址和日志级别示例。
- 确认真实 `.env` 仍被 Git 忽略。
- 再次执行 `npm run check`，然后推送 D005 收尾并同步 `main`。

## 3. 总体架构约束

- 保持 `core` 零外部依赖，不 import 其他层。
- `runtime` 负责 Loop、取消和终止条件；`memory` 负责会话；`context` 负责历史裁剪；`tools` 负责工具与标准错误；`adapters` 负责模型线格式；`observability` 负责日志和事件输出。
- 保持 Node 24、TypeScript、ESM、Vitest 和零运行时依赖。
- 所有新配置继续遵循默认值 < `agent.config.json` < `PA_*` 环境变量，非法配置直接报错。
- 文件与命令工具都限制在明确的工作区根目录；日志不得输出 API Key。
- 每一天都有独立 README、自动化测试和真实或确定性 Demo，不把教学说明重复写入 `main`。

## 4. 每日课程设计

### D006｜统一事件模型

**实现范围**

- 在 `core` 定义判别联合 `AgentEvent`，覆盖轮次开始、assistant 响应、工具调用开始、工具结果、正常完成、达到最大轮次。
- 定义同步 `EventSink` 接口；`runAgentLoop` 接收可选 sink，在现有执行路径上发出带 `turn` 和必要摘要的事件。
- 在观测层提供 sink 到现有 JSON Logger 的适配，保持 CLI 日志可读，不重复打印同一事件。
- 事件只描述事实，不包含模型密钥，也不承担持久化和 Replay。

**验收**

- 无工具、单工具、多工具和 `maxTurns` 路径的事件顺序正确。
- 工具错误结果也能产生事件，不改变 D005 的回喂行为。
- 不传 sink 时 Loop 行为保持不变。

### D007｜多轮会话与 REPL

**实现范围**

- 在 `memory` 实现进程内 `Session`，持有稳定 `id` 和完整消息历史；读取历史返回快照，外部不能直接修改内部数组。
- 每轮 Loop 完成后将本轮新增消息写回 Session，下一轮从完整历史开始。
- CLI 保留带参数的一次性提问；不带参数时进入 `node:readline/promises` REPL，输入 `/exit` 退出，空输入忽略。
- 仅实现内存会话，不做磁盘持久化、跨进程恢复或数据库。

**验收**

- 用脚本化 Provider 连续完成至少 5 轮对话，后一轮请求包含此前历史。
- 两个 Session 的历史互不污染。
- REPL 的单轮、多轮、空输入和退出行为有可重复验证方式。

### D008｜上下文字符预算与裁剪

**实现范围**

- 在 `context` 实现 `buildContext(messages, maxChars)`，将完整历史转换为单次模型请求所需的消息窗口。
- system 消息始终保留；优先保留最近消息和最新用户目标；超出预算时在 system 之后插入简短省略标记。
- system 自身超过预算时显式报错；最新用户消息单条超预算时保留末尾并标注截断；工具组超预算时优先截断 tool 内容，不拆开配对。
- assistant 的 `toolCalls` 与对应 tool 结果作为同一组处理，不生成 dangling tool call 或孤立 tool 消息。
- Loop 传给 Provider 的是裁剪后的窗口，返回给 Session 的仍是完整历史。
- 新增 `PA_MAX_CONTEXT_CHARS`，默认 24000，必须为正整数。
- 本日只做字符级近似预算，不宣称精确 token 计算，不做摘要压缩。

**验收**

- 短历史原样保留，长历史不超过字符预算。
- system、最新用户消息和工具调用配对不被破坏。
- 完整 Session 历史不因请求裁剪而丢失。

### D009｜取消与模型超时

**实现范围**

- `ChatRequest`、`AgentLoopOptions` 和 `ToolContext` 接收可选 `AbortSignal`。
- OpenAI-compatible Provider 将外部取消与现有 60 秒超时组合；外部取消与 HTTP、协议错误保持不同语义。
- Loop 在模型调用前、工具调用前和等待操作期间检查取消；新增 `cancelled` 停止原因及对应事件。
- 已结束的 run 返回 `stopReason: 'cancelled'`，不把用户取消当成模型故障抛出。
- 同步文件工具只能在操作边界响应取消；D013 的命令工具再支持终止子进程。

**验收**

- 预先取消时不请求模型。
- 取消进行中的模型请求后，不再执行后续工具或开启新轮次。
- 原有超时仍转成带原因的 `ModelError`，外部取消不误报为 HTTP 错误。

### D010｜覆盖率与周复盘

**实现范围**

- 添加 Vitest V8 覆盖率开发依赖和 `test:coverage` 脚本，CI 执行覆盖率检查。
- 覆盖率阈值：statements、lines、functions 不低于 80%，branches 不低于 75%。
- 只补核心行为测试，不为追求百分比测试 trivial getter 或第三方代码。
- 编写 D006–D010 周志，记录重排原因、完成能力、已知边界和下周入口。

**验收**

- `npm run test:coverage` 本地通过并生成报告，报告目录不进入 Git。
- CI 能复现同一覆盖率检查。
- `npm run check` 保持通过。

### D011｜write_file

**实现范围**

- 新增 `write_file`，参数为 `path`、`content`、可选 `overwrite`，默认不允许覆盖。
- 复用工作区路径保护；父目录必须已经存在，不自动递归创建目录。
- 文件存在且未指定 `overwrite: true` 时返回可读错误；写入成功后返回路径和字符数。
- 不引入原子写入、版本历史或并发锁，这些属于后续恢复与可靠性课程。

**验收**

- 新建文件、显式覆盖、拒绝默认覆盖、路径越狱、父目录缺失均有测试。
- 模型能通过工具创建文件，并在后续轮次读取结果。

### D012｜edit_file 与统一 diff

**实现范围**

- 新增 `edit_file`，参数为 `path`、`oldText`、`newText`，采用精确字符串匹配，不支持正则。
- 零匹配和多处匹配都失败并给出修复提示，只有唯一匹配才写入。
- 使用零依赖的行级 LCS 生成 unified diff，包含 `---`、`+++`、`@@` 和增减行。
- 为避免 LCS 内存失控，新旧文件任一侧超过 2000 行时返回明确工具错误，不在 CLI 中做全文件大 diff。
- 写入前再次检查工作区边界，保留原文件换行内容，不自动格式化代码。

**验收**

- 唯一匹配替换成功并返回 diff；零匹配、多匹配、路径越狱和超限均失败。
- diff 能准确展示单行修改、插入和删除。
- 修改失败时原文件保持不变。

### D013｜run_command

**实现范围**

- 新增 `run_command`，参数为 `command` 和可选 `timeoutMs`，默认 10000ms，最大 30000ms。
- 在工作区根目录通过系统 shell 执行单条命令，捕获 stdout、stderr、退出码和是否超时。
- stdout 与 stderr 分别最多回传 8000 字符，截断时明确标注；非零退出和超时返回 `isError` 结果供模型修正。
- 支持 D009 的取消信号，取消时终止子进程并回传可读结果。
- 本日不是安全沙箱：命令白名单、环境清理、资源限制和进程隔离仍属于后续安全课程，README 必须明确这一边界。

**验收**

- 成功命令、非零退出、超时、输出截断、工作目录和外部取消均有测试。
- 能执行 `npm run check` 一类命令并把失败输出回喂模型。

### D014｜标准错误语义与连续错误保险丝

**实现范围**

- `ToolResult` 增加可选结构化 `error`，包含 `code`、`message`、`retryable` 和可选 `hint`；保留 `content` 与 `isError` 作为模型线格式。
- 统一未知工具、非法 JSON、参数校验、路径、文件、编辑、命令和未知异常的错误码；Provider 不需要理解这些内部错误码。
- 实现当前工具所需的 JSON Schema 子集校验：object、string、number、integer、boolean、required、properties、additionalProperties 和 enum；不宣称完整 JSON Schema。
- 校验失败在执行工具前返回，并指出字段、期望类型和修复提示。
- Loop 新增 `maxConsecutiveToolErrors`，默认 3，可由 `PA_MAX_CONSECUTIVE_TOOL_ERRORS` 配置；成功工具调用清零，达到上限以 `tool_errors` 停止。
- CLI 对 `tool_errors` 输出未收敛原因，不伪装成正常回答。

**验收**

- 缺少必填参数、错误类型、额外字段和非法 JSON 不进入工具执行。
- 连续 3 次可重试错误后停止；中间一次成功会重置计数。
- 错误消息包含机器可读 code 和模型可读 hint，未知异常不泄露堆栈或密钥。

### D015｜综合修复 Demo

**实现范围**

- 用临时目录构造一个含失败测试的最小项目，不污染课程仓库源码。
- 通过脚本化 Provider 驱动确定性闭环：读取文件 → 运行测试失败 → 精确编辑 → 再运行测试成功 → 最终回答。
- 覆盖一次错误回喂，证明模型能看到失败测试并继续，而不是首轮终止。
- 编写当天教学 README，串讲 D006–D014 的事件、上下文、工具和错误语义如何协作。
- 最后用真实 ARK 模型做一次工作区修复验证并记录实际结果；真实模型的不确定性不进入 CI 断言。

**验收**

- 确定性集成测试证明编辑前后的命令结果从失败变为成功。
- 事件序列、完整历史、工具错误码和最终停止原因均可检查。
- D001–D015 的全部自动化检查通过，`main` 索引更新为 D015 / D100。

## 5. 统一错误与数据流

```text
Session 完整历史
  → buildContext 裁剪副本
  → Provider
  → AgentEvent 记录模型事实
  → ToolRegistry 校验并执行
  → ToolResult(content + isError + error?)
  → 错误回喂或成功继续
  → Session 保存完整新增历史
```

工具失败默认不中断 Loop；只有外部取消、达到 `maxTurns` 或连续工具错误达到上限才提前结束。模型协议错误仍属于 Provider 失败，不伪装成工具错误。

## 6. 测试与交付策略

- 单元测试覆盖正常路径和每个新增错误分支；Provider 使用脚本化假实现，不在 CI 调用真实模型。
- 文件和命令测试全部使用临时目录，测试结束清理，不依赖开发者本机文件。
- 每日依次执行 lint、typecheck、test；D010 起额外执行覆盖率检查。
- 每日从上一日分支创建，提交并推送当日分支；合并 `main` 时 README 冲突保留索引版，再更新进度和计划日期。
- D005 遗留配置只进入 D005 收尾提交，不混入 D006 功能提交。

- MCP、工具热插拔、完整 JSON Schema、沙箱和命令白名单。
- 并行工具执行、多 Agent、Replay/Eval 框架。
