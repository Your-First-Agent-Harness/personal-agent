# personal-agent v0.2.0

发布日期：2026-12-30

## G2 阶段发布

v0.2.0 标志着 Personal Agent 从单机工具 Loop 进入可扩展能力阶段：工具可以按任务动态检索和 lazy 加载，Agent 可以通过 MCP 连接外部进程，并可接入第三方 HTTP API。

## 新增能力

- `DynamicToolRegistry` 动态检索、标签评分和 lazy 工具加载。
- `tools_retrieved` 检索审计事件。
- MCP stdio Client / Server 双向工具投影。
- local/MCP 文件系统后端切换。
- Open-Meteo 外部 API Tool，包含超时、响应大小限制和结构化错误。
- D050 G2 联合验收 Demo：动态工具、外部 API、MCP 双后端。

## 验收证据

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run demo:d050
```

D050 Demo 必须输出 `D050 G2 ACCEPTANCE PASS`，并验证：

1. 动态检索命中工具且检索阶段不实例化 lazy factory。
2. 外部天气 API 返回结构化 `open-meteo` 结果，离线验收只使用显式注入的确定性 fetch。
3. MCP Client 完成 initialize、tools/list、tools/call，local/MCP 两种后端完成同一任务并关闭清理。

## 边界与限制

- 动态检索仍是确定性词法和标签匹配，不是向量语义检索。
- D050 的外部 API 证据使用离线注入 transport；这证明 API 契约和错误边界，不等同于在线可用性证明。
- MCP 当前仅支持 stdio、tools 能力和 `2025-11-25` 协议版本，不支持 HTTP、resources、prompts、sampling 或动态 listChanged。
- v0.2.0 不宣称已经完成 G3 的 100 轮长任务、成本下降或 G4 的 trace/replay/eval 门禁。

## 回归保证

D050 保留 D001–D049 的行为测试，并在合并前执行全量 lint、类型检查、测试和构建。任何 G1/G2 失败路径都必须以结构化失败或明确验收失败暴露，不能用文档描述替代运行证据。
