# D045｜安全架构评审报告

## 0. 文档元数据与结论

- 评审对象：Personal Agent Harness，D028–D044 的当前实现。
- 静态基线：D044 提交 `a427c8e7cd90292d5938af788d6c9e22443b8ab9`，D045 分支仅增补文档。
- 评审方式：源码、配置、公共导出与现有测试的静态交叉审阅；以最终提交的回归命令验证未破坏既有行为。
- 读者：维护者、安全架构师、平台/部署负责人、准备把教学项目接入真实工具的工程师。
- 配套材料：[精炼课程](d045-security-course.md)、[评审检查清单](d045-security-review-checklist.md)、[D045 总览](../README.md)。

**结论：不建议把当前默认 CLI 直接暴露给不可信用户、不可信仓库或不可信 MCP 服务，也不应把它宣称为多租户生产安全边界。** 项目已经具备若干可复核的局部控制：工具注册与可选权限、可选工具韧性、上下文字符预算、只读知识库快照的 realpath 检查、固定天气端点的网络约束，以及 D044 的精确 argv 准入、进程资源预算和 fail-closed 审计。但是，这些控制没有自动组成全局安全体系；默认 CLI 仍注册开放式 shell、写文件工具，且没有配置工具白名单或敏感操作确认。

在“单用户、本机、可信输入、可信配置、可信 MCP、工作区不含危险链接”的教学/开发场景中，可以在明确风险后继续使用。生产接入必须先完成本文 P0 项，并由真实身份、操作系统隔离、网络出口和集中审计共同兜底。

## 1. 范围、资产与假设

### 1.1 在范围内

1. 配置加载、OpenAI-compatible Provider、AgentLoop 和上下文构造。
2. D028 参数 Schema 子集、D029 Registry 权限、D030 工具韧性和 D032 多步骤发布验收链。
3. 内置文件、shell、D043 开放式命令工具与 D044 精确白名单命令工具。
4. MCP stdio client/server、远程工具适配、分页、协议握手和关闭语义。
5. D037 文件后端适配、D041 只读知识库、D042 天气工具。
6. 本地审计、敏感信息、依赖与部署信任假设。
7. 上述组件串联后的间接提示注入、权限放大、数据外传和资源耗尽风险。

### 1.2 不在范围内

- 模型供应商自身的服务端安全、模型对齐能力和第三方数据处理实践。
- 操作系统、Node.js、npm 依赖的漏洞发现与完整供应链审计。
- 对任意远程 OpenAI-compatible 或 MCP 服务的实测；本日没有发出外部攻击流量。
- Windows、容器编排和多租户控制面的兼容性认证。
- 新代码、新 Demo、依赖升级或 D046 实证。

### 1.3 关键资产

| 资产 | 需要保护的属性 |
| --- | --- |
| API key、配置文件、环境变量 | 机密性、最小可见性、可轮换性 |
| 工作区源码与数据 | 完整性、机密性、路径边界 |
| 工作区之外的宿主文件与凭证 | 不被符号链接、shell、解释器或恶意工具越权访问 |
| 模型对话、工具结果、知识库内容 | 来源可辨、隐私、上下文完整性 |
| MCP 与模型连接 | 对端可信、请求/响应完整性、有界资源 |
| 宿主 CPU、内存、进程数、事件循环和磁盘 | 可用性、公平性、可恢复性 |
| 审计记录 | 可追溯、最小泄露、持久性、抗篡改 |
| 租户/用户身份与授权策略 | 不可伪造、默认拒绝、跨租户隔离 |

### 1.4 信任假设

- 当前 CLI 没有外部身份认证层；`tenantId` 是 Registry 初始化策略，不是已认证身份。
- 模型输出、模型生成的工具参数、文件/MCP/知识库内容都是**不可信数据**，即使它们来自“正常”上游。
- `OPENAI_MODEL_BASE_URL`、Registry policy、D044 allowlist 和审计路径属于管理员配置；若攻击者能修改它们，威胁等级会显著上升。
- MCP stdio 的父进程/子进程关系是本地进程边界，不等于网络身份认证或安全沙箱。
- `workspaceRoot` 是策略输入，不是自动可信的事实；部署者必须保护其真实目录及父目录。

## 2. 架构数据流与信任边界

```text
用户 / 配置文件 / 环境变量
          │  输入与管理员策略
          ▼
       CLI main ───────────────┐
          │                    │ 默认无 allowedTools、tenantId、敏感确认
          ▼                    │
 OpenAI-compatible Provider    │
  HTTPS + Bearer API key       │  可配置 baseUrl；普通 fetch
          │                    │
          ▼                    ▼
      AgentLoop ───────► ToolRegistry
          │                    │ 可选白名单/租户/敏感确认
          │ tool result 原文    │ 参数 Schema 子集校验
          │ 回到模型            ▼
          │              内置文件 / shell / 组合工具
          │                    │
          │                    ▼
          │               宿主文件与进程
          │
          └────────────► MCP stdio client
                               │ newline JSON-RPC
                               ▼
                          MCP 子进程 / server
                               │
                               ▼
                     另一 Registry 与其工具能力
```

### 边界 B1：用户/配置 → Agent 进程

配置 loader 校验正整数和部分字符串，API key 可由环境变量注入；但 `baseUrl` 没有协议、主机或私网限制。**[代码可见]** 这属于管理员信任边界，不能把“允许自定义兼容端点”误写成任意模型输入可直接修改 URL。

### 边界 B2：Provider → AgentLoop

Provider 会解析模型返回的文本和 tool call，并继续执行。工具结果随后作为 `role: tool` 消息原样进入历史，再发送给 Provider。**[代码+测试]** 工具配对、轮次与连续错误有控制；**[未解决]** 没有内容信任标记、提示注入检测、工具结果隔离或“数据不得变成指令”的机制。

### 边界 B3：AgentLoop → Registry → Tool

D028 校验是安全漏斗之一，D029 能限制工具与敏感动作。**[代码+测试]** 但默认 CLI 的 Registry 只有 `tools` 选项，且模型参数在 JSON.parse 后直接进入该 Schema 子集与工具。**[未解决]** 没有全局默认拒绝策略、认证主体或跨工具数据流授权。

### 边界 B4：Tool → 宿主 OS

普通文件工具使用词法路径边界；`run_command` 与 D043 使用 shell；D044 使用 `shell:false`、realpath executable 和完整 argv。**[代码+测试]** 这些是截然不同的安全语义，不能统一称为“沙箱工具”。当前没有 namespace、seccomp、Landlock、chroot、网络命名空间或强制访问控制。

### 边界 B5：Agent ↔ MCP

客户端校验 initialize 协议版本、响应 ID、方法名与错误结构，并隔离通知和坏帧。**[代码+测试]** 但远端 tool schema/description/result 仍不受信；stdout 的单行和累计未换行缓冲没有字节上限。**[未解决]** 关闭和显式重建客户端不等于透明、安全、自动重连。

### 边界 B6：进程 → 日志/第三方服务

Provider 会向配置端点发送 system、对话、工具 schema 和工具结果；天气工具向固定 Open-Meteo 端点发送坐标。D044 审计写本地 JSONL。**[代码可见]** 数据保留、访问控制、跨境/第三方处理、日志删除与备份策略由部署方负责，当前不是完整隐私合规系统。

## 3. 威胁建模方法

本报告结合 STRIDE 与攻击链，而不是只按模块列“有/无功能”：

1. **画数据流**：标出来源、接收者、协议和是否跨越信任边界。
2. **枚举资产**：秘密、文件、执行能力、可用性、身份、审计。
3. **识别入口**：模型 tool call、文件路径、命令 argv、MCP 帧、Provider 响应、配置。
4. **问控制是否默认生效**：有类导出≠默认 CLI 使用；有测试≠所有部署配置安全。
5. **构造端到端攻击链**：例如恶意 Markdown → 模型读取 → 伪造指令 → shell 执行，而不是把每个模块孤立判安全。
6. **记录已有控制与剩余风险**：控制只在其语义范围内抵扣风险。
7. **给严重度与可能性依据**：避免没有上下文的“高危”标签。
8. **给处置与验证方法**：代码修复、部署限制、风险接受或 D046 实证必须分清。

### 评分尺度

严重度：

- **S4 严重**：可导致任意命令、宿主/大范围秘密泄露、跨安全主体完全失控。
- **S3 高**：可越过工作区、泄露重要数据、执行非预期高权限工具，或稳定破坏单实例可用性。
- **S2 中**：局部资源耗尽、审计/隐私缺口、需要特定配置才形成明显影响。
- **S1 低**：有限信息暴露或硬化不足，单独影响较小。

可能性：

- **L3 高**：默认路径可达，无需特殊配置或异常对端。
- **L2 中**：需要恶意模型内容、恶意/故障 MCP、可写链接或较大输入等现实前提。
- **L1 低/条件性**：需要管理员误配、本地写权限、底层故障或项目明确不支持的部署方式。

评分是当前架构的相对优先级，不是 CVSS，也不是已发生安全事件的声明。

## 6. 重点攻击链评审

### 6.1 间接提示注入 → 文件读取 → shell

```text
恶意仓库 README / Markdown / MCP result
  → read_file / knowledge_search / MCP tool
  → ToolResult 原文进入历史
  → 模型把“请运行……”误当高优先级指令
  → run_command({ command: ... })
  → /bin/sh 以当前 OS 用户执行
```

- **[代码+测试]** Loop 会执行模型 tool call 并把结果回传；Registry 可授权工具。
- **[代码可见]** 默认 CLI 没有允许列表与敏感确认，且 `run_command` 使用 shell。
- **[未解决]** 没有可靠的提示注入分类器能单独证明此链不存在。
- **[文档建议]** 同时切断多处：默认不注册 shell；把外部内容标为不可信；对写/执行/网络动作要求基于认证主体的确认；命令用精确业务规则；最后在 OS 沙箱运行。
- **[D046 待实证]** 只在临时目录放无害 canary 和 marker，验证当前默认链路及加固后链路；不得把一次模型未服从当成修复证据。

### 6.2 符号链接逃逸

`resolveInWorkspace` 做 `path.resolve(root, input)` 和前缀比较，可以拒绝 `../outside`，但不会把 `root/link` 解析成真实目标。`read_file`、`write_file`、`edit_file` 后续 Node FS 调用会按操作系统语义跟随链接。

- 最终文件链接：词法路径仍在 root，真实目标可在 root 外。
- 父目录链接：`root/linkdir/file` 的父目录可能指向外部。
- TOCTOU：检查、stat、read/write 之间路径可能被替换；单纯增加一次 realpath 也不能完全关闭竞态。
- **[文档建议]** 在支持的平台上使用可信 dirfd、逐层 no-follow、打开后校验；否则用独立 OS 沙箱和只读挂载，并限制不可信用户创建工作区链接。
- **[D046 待实证]** 在临时 root/outside 中验证读、写、编辑和父目录链接；测试必须清理，不接触真实宿主秘密。

### 6.3 恶意 MCP 的两种角色

1. **恶意 server 对 client**：输出无换行大数据、伪造描述、诱导工具调用、返回超大数据或永远不响应。协议 ID/版本校验和 timeout 只覆盖其中一部分。
2. **恶意 caller 对 server**：如果攻击者能写 stdin，toolNames 仅限定可调用集合，不能证明调用者身份。父进程启动模型下这是本地信任假设，不是互联网认证。

**[文档建议]** 将 MCP server 包在最小权限进程中；client 设置帧/结果上限、服务级工具审批、敏感级别与单独审计；不要把不可信 MCP 工具自动加入高权限 Registry。

### 6.4 D044 白名单不是能力沙箱

精确 argv 能阻止在允许命令后追加 `;`、管道或额外参数，这是明确且已测试的收益。但若规则允许解释器执行一段代码，该代码仍是当前用户的普通进程；一次性 cwd 不会阻止绝对路径访问，最小 env 也不会撤销网络或文件权限。

此外，审计 completion 写失败发生在副作用之后，只能显式报错，不能回滚。审计决策失败不 spawn 是 fail-closed；不是整个执行过程的事务机制。

## 7. 目标安全架构（仅为建议）

```text
已认证调用方
   │ 身份、会话、租户、请求 ID
   ▼
授权代理 / Policy Gateway
   │ 默认拒绝；主体 × 工具 × 动作 × 资源 × 数据级别
   ▼
Agent Orchestrator
   │ 内容来源/污点、上下文预算、动作确认、幂等键
   ├──────────────► 模型出口代理：固定端点、无凭据重定向、响应/超时上限
   │
   ▼
最小权限 Registry
   │ 每主体独立视图；敏感工具显式审批
   ▼
窄业务工具 / 精确命令规则
   │ 输入与输出字节、超时、并发、重试、取消
   ▼
OS 沙箱与网络出口代理
   │ 只读 root、限定 writable dir、非特权用户、rlimit/cgroup、无默认网络
   ▼
集中审计与告警
   │ 访问控制、保留、签名/WORM、隐私脱敏、故障策略
```

以上全部属于 **[文档建议]**，不是 D045 新增代码。优先顺序：

### P0：不可信输入或真实秘密接入前

1. 默认 CLI 改成最小工具集；shell/write/MCP 需显式开启并配置 allowedTools、认证主体和敏感确认。
2. 修复文件路径真实目标与竞态边界；在修复前禁止不可信工作区链接。
3. 为 Provider 和 MCP 增加网络/帧/结果/超时上限与出口策略。
4. 把间接提示注入当作必然输入，实施动作级最小权限，而非只加 system prompt。
5. 不可信命令移入真正 OS 沙箱；D044 只负责应用层准入与审计。

### P1：生产试运行前

1. 集中审计、权限/保留、篡改检测、隐私审查和告警。
2. 全工具默认资源预算、磁盘与进程限制、幂等/补偿语义。
3. 依赖漏洞、SBOM、签名与许可证门禁。
4. 多平台测试、故障注入、恶意 MCP/Provider 测试与风险接受记录。

## 9. 评审结论、风险接受与签署建议

### 当前可接受

- 本机教学、受控代码演示、无可信秘密的隔离开发环境。
- 使用者理解默认 shell 与文件工具的能力，不接入不可信 MCP/仓库。
- D044 作为“精确命令准入与审计”组件单独复用，并接受其非 OS 沙箱边界。

### 当前不可接受

- 面向公网或多租户直接暴露默认 CLI/stdio 工具能力。
- 让 Agent 在含有生产凭证的个人账户下处理不可信内容并保留 open shell。
- 将 `sandboxed_command`、临时 cwd、字符预算或 JSONL 审计宣传为完整安全隔离。
- 把现有单元测试数量当作攻击抵抗力的覆盖率。

### 正式评审应要求的签署

| 角色 | 必须确认 |
| --- | --- |
| 维护者 | 风险矩阵与源码一致；P0 有 owner、期限和回归用例 |
| 安全负责人 | 威胁模型、剩余风险、测试证据和禁用场景成立 |
| 平台/部署负责人 | 身份、OS 沙箱、网络出口、文件权限、审计和隐私配置真实生效 |
| 产品/业务负责人 | 明确接受或拒绝剩余风险，不把教学项目的限制隐藏给最终用户 |
