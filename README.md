## 今天讲什么

### 1. 为什么又从零写一个

现成框架能让你今天跑起来，但不会告诉你明天为什么坏。这个项目只回答三个问题：

1. 一次工具调用从模型输出到结果回填，中间到底发生了什么。
2. 上下文什么时候开始腐烂。
3. Agent 出错时从哪里查。

这三问也是整个项目的取舍标准：任何时候出现分歧，选那个**更能被解释**的方案。

### 2. 关卡为什么这样定

关键不是"100 天做完一个项目"，而是每个阶段结束时**有外部证据**：

| 关卡 | 时点 | 外部证据 |
|---|---|---|
| G1 | D25 | 陌生人能安装，并完成一次「读文件 → 改代码 → 跑测试」 |
| G2 | D50 | 工具可插拔、MCP 双向通、能接外部系统 |
| G3 | D70 | 100 轮不跑偏、成本降 40% |
| G4 | D85 | trace 可回放、评测集进 CI、20 名内测用户 |
| G5 | D100 | v1.0 发布 |

"我觉得做完了"不算证据，别人能跑通才算。

### 3. 不做的事

不做低代码平台、不做多模态、不做模型训练、不做花哨 UI。
范围一旦扩散，100 天必然烂尾——第一天的纪律比第 100 天的功能更重要。
